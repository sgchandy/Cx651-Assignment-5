(1) In the one-process run, peak USS was 393,340 KB, peak PSS was 393,394 KB, and peak RSS was 394,580 KB. Since there is only one process, most of the memory is private, which is why USS, PSS, and RSS are all very close.

(2) In the five-process run, each process still used about the same amount of memory. On average, peak USS was about 393,324 KB, peak PSS was about 393,376 KB, and peak RSS was about 394,620 KB per process. Since the processes are not sharing the input data, each process keeps its own copy in memory.

(3) In the normal run, each process peaked at about 393,320-393,336 KB USS, 393,368-393,388 KB PSS, and 394,572-394,676 KB RSS. These values are close because each process has its own input and output data. With mmap, each process's RSS still peaks around 394,600 KB, but USS peaks around 196,700-198,800 KB for four processes because they share the read-only input. Their PSS peaks between about 237,800 and 295,100 KB, it includes private memory plus each process's share of shared pages. After the other processes exit, the last process's USS, PSS, and RSS rise to about 393,336, 393,377, and 394,596 KB. In the plot, each process has solid RSS, dashed PSS, and dotted USS lines. The normal lines rise together as each process loads and touches its own image data. For mmap, RSS stays high while USS is lower and PSS lies between them, showing that pages are shared. PSS can shift upward as processes finish and fewer processes share the mapping. The logged runs took about 11 minutes 42 seconds normally and 10 minutes with mmap, likely because sharing the input reduces memory pressure and copying.

(4) A minor page fault happens when the required page can be found in memory and does not need to be read from disk. A major page fault happens when the page has to be loaded from disk. So, zero major page faults means none of the page faults required disk I/O.
